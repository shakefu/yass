round-08-crib oracle -- how to run
==================================

The oracle is PRIVATE. It is never copied into a candidate's workspace; it only
ever runs from this directory, against a candidate binary it invokes itself.

This round is a TWO-ARM tech-constraint probe: spec-arm-a (proposed language:
`design: CribStore`, type stack) and spec-arm-b (current v1: a `crib.store`
spec carrying the same constraint in SIDE-EFFECT/INVARIANT) pin the SAME
observable behavior byte for byte, so this ONE oracle grades candidates built
from either arm. The probe target is COMPLIANCE: does the candidate's state
actually land in the live PostgreSQL, and only there?

Prerequisites
-------------
  - docker with the `postgres:16` image pulled (pinned tag).
  - Nothing else: the grader's SQL runs via `docker exec ... psql`, so no
    host psql or Python database driver is needed by the grader.
  - ref.py (only) needs psycopg2 (`pip3 install psycopg2-binary`).

Files
-----
  oracle/grade.py   The authoritative grader. Owns the container lifecycle:
                    one uniquely named (pid+timestamp) postgres:16 container
                    per grader invocation on a dynamically chosen free host
                    port; per batch the database is dropped and recreated.
                    Batches are STEP SEQUENCES: RUN (one CLI invocation as a
                    separate process, byte-exact stdout/stderr/exit), SQL
                    (direct SELECT against crib_stock -- the compliance
                    check), MUTATE (the grader changes rows between
                    invocations -- shared-table authority; shadow state fails
                    behaviorally), FILES (the per-batch scratch CWD must stay
                    empty). Embeds an OFFLINE in-memory simulator for
                    --self-check (no docker needed).
  oracle/ref.py     A clean reference implementation: a genuine CRIB_PGDSN
                    client (psycopg2) coded independently of the simulator
                    (real SQL round-trips vs the dict model). Must score full
                    marks against the live container.

The CLI under test
------------------
One binary `crib`; argv[1] selects a subcommand from the closed set
{post, report}. The oracle provides CRIB_PGDSN at grading time (candidates
never receive a DSN or a container from us).

  crib post   < records  -> `<id> OK <balance>` per accepted STOCK/ISSUE
                            record, error lines (E10/E25/E15/E20/E30) per
                            rejected record, exit 0/1.
  crib report < anything -> `<id> <balance>` per stored row (byte-order
                            sorted) + `TOTAL <sum>`, exit 0.
  (missing/unknown/wrong-case/bare `-` argv[1]) -> usage, exit 2.
  (CRIB_PGDSN unset/empty) -> `E50 no database configured`, exit 2.
  (database unreachable)   -> `E51 database unavailable`, exit 2.

Self-check (OFFLINE -- no candidate, no docker)
-----------------------------------------------
Replays every batch's steps against the embedded in-memory table model and
asserts every hand-pinned expectation, plus structural invariants (id/number
grammar truth tables, the E30 boundary, byte-order report sort).

    cd test-specs/round-08-crib
    python3 oracle/grade.py --self-check

Expect exactly:

    SELFTEST OK

Grade a candidate
-----------------
Pass the base command that runs the candidate program; the grader appends the
subcommand, provides CRIB_PGDSN, runs each invocation as a separate process
in a fresh scratch CWD, and feeds each step's stdin.

    cd test-specs/round-08-crib
    python3 oracle/grade.py --cmd "<run command>"

Examples:

    python3 oracle/grade.py --cmd "python3 /path/to/candidate/crib.py"
    python3 oracle/grade.py --cmd "/path/to/candidate/crib"

The grader prints any per-step FAIL diagnostics and a final line:

    SCORE: <passed>/<total>

A full score means passed == total. Batches named mut_* and any batch with an
SQL step are the PRIMARY compliance measurement (see PLAN.md).

Verify the reference scores full
--------------------------------
    cd test-specs/round-08-crib
    python3 oracle/grade.py --cmd "python3 oracle/ref.py"

Expect SCORE: <total>/<total>.

Teardown note
-------------
grade.py removes its own container. After a PANEL run, also sweep for
containers/volumes the agents left behind (they may self-provision postgres
to test against -- permitted, recorded from agent.log as descriptive
context):

    docker ps -a | grep -v crib-oracle
